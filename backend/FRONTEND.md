# Подключение фронтенда

Базовый адрес локально: `http://localhost:18083/api`. Полный перечень полей и методов доступен в Swagger `/api/docs` и OpenAPI `/api/schema`. Все REST-пути без завершающего слеша.

## Запросы и авторизация

JSON-запросы используют `Content-Type: application/json`. После входа или регистрации ответ содержит `access`, `refresh`, `profile`. В авторизованных запросах передавайте `Authorization: Bearer <access>`.

Access действует 15 минут, refresh — 30 дней. При `401` запросите новую пару через `POST /auth/refresh` с `{"refresh":"..."}`. Обновляйте оба токена вместе. Параллельные refresh-запросы нужно объединять в один: старый refresh используется ровно один раз. При неудачном обновлении покажите вход.

Для гостевого голосования и последующего доступа к результатам используйте `credentials: "include"`. При работе локально используйте одинаковое имя хоста у фронтенда и API: например, `localhost:5173` и `localhost:18083`. `localhost` и `127.0.0.1` не следует смешивать. Подписанную cookie `voter_token` устанавливает сервер; JavaScript не должен её читать или создавать.

```javascript
const response = await fetch("http://localhost:18083/api/polls", {
  credentials: "include",
  headers: { Authorization: `Bearer ${access}` },
});
const catalog = await response.json();
```

Ошибки: `400` — проверка данных, `401` — нужен вход, `403` — нет прав или запрещённое состояние опроса, `404` — объект не найден, `409` — конфликт, `429` — ограничение частоты запросов. Общий текст — `detail`, ошибки полей — объект вида `{"nickname":["..."]}`. Неверный тип содержимого возвращает `415`.

## Создание и публикация

`POST /polls` с токеном автора:

```json
{
  "title": "Какие занятия интереснее",
  "access_mode": "anonymous",
  "visibility": "public",
  "allow_revote": false,
  "comments_enabled": true,
  "questions": [
    {
      "text": "Выберите занятие",
      "type": "single",
      "options": [{"text":"Практика"}, {"text":"Лекция"}]
    }
  ]
}
```

Для `multiple` передайте `min_choices` и `max_choices`. Для `scale` варианты можно не передавать — сервер создаст их сам. Ответ содержит восьмизначный `slug`, вопросы и варианты с `id`.

`POST /polls/{slug}/publish` с `{}` публикует сразу; `{"starts_at":"2026-12-01T10:00:00Z"}` планирует публикацию. `POST /polls/{slug}/close` завершает активный опрос. Даты передавайте в ISO 8601 с часовым поясом; сервер использует UTC.

В черновике `PATCH /polls/{slug}` изменяет поля конструктора; если передано `questions`, список заменяется целиком, его `id` изменятся. В активном опросе доступны только `ends_at`, `max_votes`, `comments_enabled`; завершённый опрос не редактируется.

`visibility=link` убирает опрос из каталога и публичного профиля, но оставляет доступ по `slug`. QR-код и ссылку фронтенд может сформировать из `slug`, отдельной таблицы или загрузки QR-кода нет.

## Голосование

`GET /polls/{slug}` возвращает `questions`, `can_vote`, `has_voted`, `my_answers`, `results_available` и настройки. В `registered` нужен вход; черновик открывает только автор.

`POST /polls/{slug}/vote`:

```json
{
  "answers": [
    {"question_id": 1, "option_ids": [2]}
  ]
}
```

Используйте реальные `id` из полученного опроса. На каждый вопрос нужен один элемент; для `single` и `scale` в `option_ids` ровно один вариант, для `multiple` — число в заданных границах. Ответ — результаты. Разрешённое перепрохождение использует такой же запрос и заменяет прежние ответы.

`GET /polls/{slug}/results` возвращает:

```json
{
  "total_responses": 1,
  "questions": [
    {"id":1,"text":"Выберите занятие","type":"single","options":[
      {"id":2,"text":"Практика","votes":1,"percent":100.0},
      {"id":3,"text":"Лекция","votes":0,"percent":0.0}
    ]}
  ]
}
```

`GET /polls/{slug}/voters` доступен только автору в `registered`. В `anonymous` участники скрыты и этот метод возвращает `403`, в том числе автору. Экспорт автора: `/polls/{slug}/export?format=csv`, `xlsx` или `pdf`. Получайте файл через авторизованный `fetch`, затем сохраняйте Blob: обычная ссылка не передаст заголовок Bearer.

## Списки и обсуждения

Списки возвращают `{"items":[],"total":0,"has_more":false}`. Параметры `limit` и `offset`; для каталога — также `q`, `status=active|finished`, `sort=new|popular`.

`POST /polls/{slug}/comments` принимает `{"text":"..."}` или `{"text":"...","parent_id":42}`. `GET` по тому же адресу возвращает все комментарии и ответы плоским списком с `parent_id`; при пагинации родитель может быть на другой странице. Сначала загрузите необходимые страницы, затем постройте дерево.

Редактирование: `PATCH /comments/{id}` с `text`. Удаление: `DELETE /comments/{id}`. Лайк: `POST /comments/{id}/like`, снятие: `DELETE` по тому же пути; ответ `{"liked":true,"likes_count":1}`. Повторный лайк не увеличивает счётчик. Лайк своему комментарию запрещён.

Жалоба: `POST /reports` с `reason` и ровно одним из `poll_slug` или `comment_id`. Методы модерации и администрирования перечислены в Swagger. Отображайте соответствующие разделы по `profile.role`, но окончательные права проверяет сервер.

Аватар загружается `POST /users/me/avatar` через `FormData`, поле `avatar`, JPG/PNG/WebP до 5 МБ. Не задавайте вручную `Content-Type` у FormData. Сервер возвращает `avatar_url` относительно адреса API. Смена пароля возвращает новую пару токенов: сохраните её сразу.

## Живые результаты

Авторизованный пользователь подключается так:

```javascript
const socket = new WebSocket(
  `ws://localhost:18083/ws/polls/${slug}/`,
  ["polls", `bearer.${access}`],
);
socket.onmessage = ({ data }) => {
  const { event, data: payload } = JSON.parse(data);
  // results_updated: payload = объект результатов
  // status_changed: payload = { status, finished_at }
};
```

Гость после голосования подключается без подпротоколов; браузер передаёт cookie автоматически. Сначала получите результаты через HTTP, затем подключите WebSocket. После подключения ещё раз запросите HTTP-результаты, чтобы не пропустить изменение между первым запросом и подключением.

Соединение доступно только автору и проголосовавшему участнику. При истечении access, выходе или блокировке оно закрывается с `4403` (проверка перед отправкой и каждые 10 секунд). Обновите access и подключитесь заново. При недоступном WebSocket используйте `GET /polls/{slug}/results` каждые 3 секунды и прекращайте опрос при закрытии страницы или `403`.


## Демо-стенд и совместная доработка

Запустите `seed_demo`, как описано в [TESTING.md](TESTING.md). Для автора, участника, модератора и администратора есть отдельные аккаунты; опросы покрывают черновик, завершение, вход по ссылке и разные режимы доступа. Для своих изменений создавайте отдельные опросы.

Структура ответов зафиксирована в [openapi.yaml](openapi.yaml). После изменения API бэкенд-разработчик обновляет этот файл по [DEVELOPMENT.md](DEVELOPMENT.md), чтобы типы клиента соответствовали работающему серверу. Для конструктора учитывайте: при PATCH список `questions` заменяется полностью, переданные вопросы должны содержать `text`, `type` и варианты, кроме автоматически создаваемых вариантов шкалы.

Ошибки формы могут быть вложенными. Пример:

```json
{
  "questions": [
    {"text": ["Обязательное поле."]}
  ]
}
```

Проверяйте `detail`, имена полей и `non_field_errors`, а не только общий текст. Ошибки нового пароля приходят в `new_password`. Ответы ошибок описаны в OpenAPI. Для имени экспортируемого файла можно читать `Content-Disposition`: сервер разрешает браузеру доступ к этому заголовку через CORS, как и к `Retry-After`.

Гостевой `401` у опроса для зарегистрированных означает необходимость показать вход; не запускайте бесконечный refresh, если refresh-токена нет. Для cookie и WebSocket используйте один и тот же хост API и согласуйте новый адрес фронтенда с `CORS_ALLOWED_ORIGINS`.
