## О проекте

Веб-приложение для создания и прохождения опросов. Опрос может состоять из одного вопроса или целой анкеты, быть публичным или доступным только по ссылке. Участники голосуют, обсуждают вопросы и видят обновление результатов без перезагрузки страницы.

В проекте реализован бэкенд: **44 REST-операции, WebSocket результатов и 13 предметных таблиц**. Фронтенд разрабатывается отдельно.

## Возможности

| Раздел          | Что доступно                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Учётная запись  | Регистрация, вход по почте, профиль, аватар и смена пароля                                      |
| Опросы и анкеты | Создание черновиков, редактирование, публикация и завершение                                    |
| Вопросы         | Один ответ, несколько ответов или шкала от 1 до 5                                               |
| Доступ          | Анонимное прохождение или только для зарегистрированных; каталог или ссылка                     |
| Голосование     | Проверка выбранных вариантов, защита от повторного голоса и разрешённое автором перепрохождение |
| Расписание      | Отложенная публикация, завершение по времени или числу прохождений                              |
| Результаты      | Число голосов, проценты, обновления через WebSocket                                             |
| Экспорт         | Выгрузка результатов в CSV, XLSX и PDF                                                          |
| Обсуждения      | Комментарии, ответы на комментарии и лайки                                                      |
| Модерация       | Жалобы, предупреждения, ручные блокировки и автоблокировка за три предупреждения                |

### Роли пользователей

- **Гость** проходит доступные анонимные опросы. Сервер определяет браузер по подписанной cookie.
- **Пользователь** создаёт опросы, голосует, комментирует и отправляет жалобы.
- **Модератор** рассматривает жалобы, удаляет нарушения и выдаёт предупреждения.
- **Администратор** дополнительно управляет ролями и блокировками пользователей.

В анонимном режиме автор получает сводные результаты без списка участников. В режиме для зарегистрированных автор может просматривать участников и их ответы.

## Быстрый запуск

Потребуется **Docker Desktop с Linux-контейнерами**. Устанавливать Python и PostgreSQL на компьютер для этого способа запуска не нужно.

### 1 Подготовить окружение

Откройте терминал в корне проекта и перейдите в папку бэкенда:

```powershell
cd backend
```

Если файла `.env` ещё нет, создайте его из примера:

```powershell
Copy-Item .env.example .env
```

В `.env` задайте собственные `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`. Укажите тот же пароль в `DATABASE_URL`. Уже настроенный `.env` заменять не нужно.

### 2 Запустить приложение

```powershell
docker compose -p codex-polls-er4 up -d --build
```

Compose дождётся готовности PostgreSQL, применит миграции и запустит API и планировщик. Роли `user`, `moderator` и `admin` создаются автоматически.

### 3 Проверить запуск

Откройте [Swagger](http://localhost:18083/api/docs) или [проверку состояния API](http://localhost:18083/api/health). Исправный API вернёт:

```json
{ "status": "ok" }
```

По умолчанию приложение доступно на порту **18083**. Если он занят, измените `API_PORT` в `.env` и повторите запуск. PostgreSQL и Redis доступны только внутри сети Compose.

## Документация API

Адреса ниже доступны после запуска контейнеров.

| Ресурс        | Адрес                                                   |
| ------------- | ------------------------------------------------------- |
| Базовый адрес | `http://localhost:18083/api`                            |
| Swagger       | [Открыть документацию](http://localhost:18083/api/docs) |
| OpenAPI       | [Получить схему](http://localhost:18083/api/schema)     |
| Проверка БД   | [Проверить API](http://localhost:18083/api/health)      |
| WebSocket     | `ws://localhost:18083/ws/polls/{slug}/`                 |

REST-пути используются **без завершающего слеша**, путь WebSocket — со слешем. Данные передаются в JSON; загрузка аватара использует `multipart/form-data`.

Для авторизованных запросов передавайте заголовок:

```http
Authorization: Bearer <access>
```

Access-токен действует 15 минут, refresh-токен — 30 дней. Гостевые запросы с фронтенда должны сохранять cookie: используйте `credentials: "include"`.

Подробные примеры, форматы ответов и подключение WebSocket находятся в [инструкции для фронтенда](backend/FRONTEND.md). Сохранённая схема доступна в [openapi.yaml](backend/openapi.yaml).

### Модель данных

| Область                     | Таблицы                                                 |
| --------------------------- | ------------------------------------------------------- |
| Пользователи и сессии       | `roles`, `users`, `refresh_tokens`                      |
| Предупреждения и блокировки | `warnings`, `bans`                                      |

У `comment_likes` составной первичный ключ `(user_id, comment_id)`. Служебные таблицы Django не входят в эти 13 таблиц.

## Полезные команды

Все команды выполняются из папки `backend`.

**Создать администратора** — команда запросит почту, никнейм и пароль:

```powershell
docker compose -p codex-polls-er4 exec backend python manage.py createsuperuser
```

**Посмотреть состояние контейнеров и журналы приложения:**

```powershell
docker compose -p codex-polls-er4 ps
docker compose -p codex-polls-er4 logs -f backend scheduler
```

**Пересобрать приложение после изменения кода:**

```powershell
docker compose -p codex-polls-er4 up -d --build
```

**Остановить проект с сохранением данных:**

```powershell
docker compose -p codex-polls-er4 down
```

База и аватары хранятся в Docker-томах. Добавление `-v` к команде остановки удалит эти тома вместе с данными.

## Проверки

Для первоначальной версии **все 56 тестов прошли на PostgreSQL**. Проверяются API, права доступа, ограничения БД, анонимность, отзыв токенов, WebSocket и одновременные запросы.

```powershell
docker compose -p codex-polls-er4 exec backend python manage.py test --verbosity 2
docker compose -p codex-polls-er4 exec backend python manage.py check
docker compose -p codex-polls-er4 exec backend python manage.py makemigrations --check --dry-run
docker compose -p codex-polls-er4 exec backend python -m ruff check .
```

Тесты используют отдельную базу `test_polls`. Вспомогательный запуск без Docker и особенности режима SQLite описаны в [README бэкенда](backend/README.md).
